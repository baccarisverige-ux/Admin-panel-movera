# R3 — ActionSpec and command engine

Dependency: R2

Frontend-only scope:
Make ActionSpec the single business-action registry with permission, scope, allowed states, reason, expected version, idempotency, truthful operation states, conflicts and audit.

Stack rule:
- stay draft until R2 is the verified base
- do not merge out of order
- no backend, Rider or Driver changes
- use the typed simulation and AdminApi boundary

Definition before Ready for review:
- every business action resolves through ActionSpec
- permission, scope, reason, expected revision and idempotency are enforced by the simulation API
- duplicate submit produces one effect
- stale revision produces a truthful 409 conflict
- timeout is shown as unknown rather than failed and retry can reuse the same key
- audit records operation id, actor, target, before, after, reason and result
- TypeScript, lint, unit tests, Playwright and build pass
